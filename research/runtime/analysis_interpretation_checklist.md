# 最终分析与结果展示解释清单

2026年11月5日。范围为已完成的E1/控制证据及预先固定的E0–E4解释规则；主实验结果应由实际产物填写。冻结代码和主统计保持不变。

## 已有事实可以怎样使用

| 已核实证据 | 可支持的表述 | 必须保留的边界 |
|---|---|---|
| W同bank：100组×4，49组两reward可区分、41组仅Pair、10组均恒定 | 在同一批候选上，Pair增加41个百分点的可区分组 | 不证明训练收益、泛化或视觉依据改善；“仅Exact变化”按定义不可能，发现须排错 |
| 394/400合法；41个Pair-only中39组四个均合法；另1个混合组的合法候选间也有差异 | 额外区分大部分来自合法错误排列之间，无法全部归于格式 | 不把39/41或40/41解释为因果贡献比例；分层是新增诊断，不替代100组主统计 |
| 同20个开发食谱：W照片输入Exact 7/20，空白图1/20，两者valid均20/20 | 移除照片后该小样本的排序表现下降 | 空白是强分布变化；核对文字/像素预算变化，不能据此证明正确grounding或排除所有泄漏 |
| 照抄显示顺序在905题上micro Exact为38/905、macro约4.358% | 这是固定展示manifest上的确定性parser baseline | 不是模型推理结果；不能把micro和macro互换 |
| 均匀随机合法排列的Exact期望1/24、Pair期望1/2 | 可作解析参照线并写明假设 | 是期望值，未进行一次随机模型实测；本任务自由排序的机会率不是原RecipeQA四选一的25% |

证据位置均相对服务器根目录`/root/autodl-tmp/rl_recipeqa`：`results/e1_w_bank/{summary,format_stratification}.json`、`results/w_blank_control/summary.json`、`data/controls/analytic_controls.json`。说明性候选见本目录`bank_format_stratification.md`；不能由一个精选例估计总体频率。

## 汇总前的必过核验

- [ ] 每模型E0为905题/597食谱；E3为60食谱×24展示；E4每模型40响应/160图。固定manifest完整覆盖，技术失败先修复；模型invalid保留为零分并另报。
- [ ] 用实际checkpoint身份、weight hash、manifest hash、processor/prompt/parser配置关联所有文件；不能假定不同summary中的`group_001`代表同一模型。
- [ ] 三主模型均来自同W和同预生成访问流，checkpoint只用固定200开发题选择。不得由test、orbit或人工个例重新选点。
- [ ] 差值按模型身份查找，再统一为Pair−Exact、Pair−SFT。底层JSON常存`left_minus_right`，模型顺序可能相反，需同时翻转点估计和区间端点。
- [ ] 图、表、案例标明集合与计分协议。调试32题过拟合、开发选点、解析控制、W bank和正式test各有明确标签。

## E0主表、曝光与成本

主表至少列：模型与起点、训练seed、共同最大访问预算、选中checkpoint步数、选中点实际prompt访问、生成completion/监督target数量、Exact/Pair/valid recipe-macro、全分支训练成本。附题级micro及每seed原值。

- [ ] 主2pass最大预算均为2,048次prompt访问。SFT每更新8次访问，RL每更新2个prompt组和8个候选；选中点分别为`8×SFT步数`、`2×RL步数`次访问。开发选择早停快照后，实际选中模型曝光未必相同，表述为“共同最大预算与统一选点协议”。
- [ ] 两个RL各完整预算8,192个生成completion；SFT有2,048个监督target。相同epochs、访问上限或更新数都不表示equal FLOPs。
- [ ] Base、W的训练与选点成本分列。W也可能改变语义能力，不能将Base→W全部解释为格式修复。
- [ ] 选中最佳点的精度配完整分支/选点成本；如另报“到该快照的累计成本”，写明它是完整开发搜索后识别的快照，不能隐藏后续搜索成本。
- [ ] 区分训练循环wall、GPU-active计时或代理、预处理、保存、开发评测、终点评测和平台计费wall。`step_times`不是硬件利用率积分，训练elapsed也不是equal-compute证据。
- [ ] 租金按实例实际计费时长含下载、CPU处理、空闲和失败重跑；不要用GPU训练小时乘价格冒充总费用。
- [ ] CPU线程或运行资源变化使pilot外推失准时，用正式日志更新估计，保留旧估计与适用条件；不能把约4.5–4.7小时训练循环组件当整项目已确认耗时。
- [ ] 四pass SFT如触发：保留主2pass比较，独立列出额外监督访问/成本；其warmup也从8变16步，不能称只改变训练时长的单因素实验。若削弱RL优势，收窄结论。

## 区间与独立样本单位

- [ ] E0在每食谱内先平均，再对597个食谱平均。配对bootstrap每次重采同一批食谱，并保留同食谱全部题；2,000次、95%区间、统计seed按冻结协议。
- [ ] E3的1,440响应仍只有60个食谱单位；每格360次观察也不是360个独立食谱。E4每模型40个食谱，四图和两名审核者都不扩充独立N。
- [ ] 一个训练seed的recipe bootstrap只描述测试食谱抽样不确定性，不包含重新训练的波动。不能把seed42的窄区间写成算法稳定性；有seed2时逐seed列出效应、平均/范围，不把所有预测拼成扩大后的独立样本。
- [ ] CI跨零表示当前证据不能区分，不等于等效。若给两项正式主比较p值，按计划Holm处理；不要从六关系或16个矩阵格里挑显著项充当确认性发现。
- [ ] 全0/全1指标的percentile bootstrap可能退化为`[0,0]`或`[1,1]`。报告实际计数及退化限制，不能声称总体概率精确等于边界；如加边界区间，标为补充敏感性并写清假设。

## E1与训练动态

- [ ] 同bank对照必须复用完全相同的原文候选。两个训练分支的on-policy日志分布不同，其非恒定率曲线仅为各自训练过程描述。
- [ ] E1图注明“100个固定开发题，各4个W采样，同候选双打分”；400个候选不是400个独立组。当前49/41/10图没有内嵌N/G，最终caption必须补全。
- [ ] 同时展示Exact、Pair、valid、长度与截断情况；不存在的entropy/clip指标写缺失，不补0、不从猜测构造曲线。
- [ ] 更多可区分组并不自动说明更好的梯度或泛化；Pair同时改变密度、错误偏好及方向，不能据此给出density单因素因果结论。
- [ ] 全同reward组的task advantage为零，不等于参数必然不动：Adam历史动量等仍可能有作用。也不能把全对恒定组概括为失败。
- [ ] 学习曲线用真实累计训练wall与实际访问数标注，另列dev时间；只有4个开发点时直接连线示意，不平滑出不存在的观察。
- [ ] 各分支四个开发点的时间支持可能不重叠：例如SFT已训练结束时RL尚未到第一个开发点。只能比较实际观察到的成本曲线，不能靠插值作equal-compute结论；并列给出共同512/1024/1536/2048次实际访问处的真实开发结果。
- [ ] q与Kendall tau是仿射关系，不能把两者当独立消融。均匀排列的零方差概率是数学控制，不能替代W的真实分布。

## E2局部错误

- [ ] 六关系、首末rank、中间关系分别命名。目标rank 2/3是所选四图中的中间，不必是整份食谱的中段。
- [ ] q七档和invalid分开；合法全逆序的q=0与invalid不是同一种错误。六关系热图使用recipe-macro，现有q分布图使用question-micro，图注必须写明。
- [ ] Pair提高、Exact不提高时，先看哪些关系改善、是否5/6堆积，再描述局部收益；不能仅由端点提升推断视觉依据改善。
- [ ] 若分析合法条件子集，保留全量主指标，并用预定义共同子集或同题迁移说明构成；不同模型各自valid子集不能直接当同人口比较。

## E3展示稳定性与位置矩阵

- [ ] 同一题的像素集合和文字固定，显示位置/A–D绑定改变后，正确标签必须同步映射。先恢复语义身份再比较输出，不能比较四字母字符串是否相同。
- [ ] 在各主终点对同10个开发输入真正执行两次greedy，分别保存独立输出文件并核对输入/权重；重跑相同PredictionStore被skip不算第二次推理。若链路有噪声，暂停展示归因并如实报告。
- [ ] 同时给A=24展示平均Exact、B=全部24正确、C=最大有效语义候选频率/24及K=成功次数。Invalid始终占分母，不形成modal候选。
- [ ] 高C低A表示稳定错误。A提高而B未提高只支持平均呈现收益；不要把“答对过一次”或pass@24当能力边界，照抄输入顺序也恰有一次正确。
- [ ] 不把905题E0准确率与60题E3平均直接相减称“shuffle drop”。需要差值时使用同60题、同快照、同布局的配对基准；更大drop可能是位置脆弱性，不能反向称时间推理更强。
- [ ] M的行是目标序位，列是输入槽位，值是该图放回正确rank的比例；不是attention图或因果机制图。原值与行中心化值均展示，跨模型同色标，同recipe顺序。
- [ ] 位置差异缩小可能来自整体准确率或天花板变化。必须结合原值、中心化、配对变化和invalid，不从单个明亮格解释内部机制。

## E4显式过程与人工依据

- [ ] 单独解析图→step字段和唯一Order字段。Order有效与完整格式有效分别报告；不能用主短答案parser扫描整段解释。
- [ ] 来源step ID先转为模型实际看到的1-based编号。审核包显示实际可见/裁剪后的文字，不能让审核者利用模型未见的完整body替模型补依据。
- [ ] 来源映射正确和排序自洽只表示与标注/输出一致，不证明像素中唯一可判定，更不等于隐藏CoT忠实性。
- [ ] 每方法固定40响应、160图。两人原始标签和分歧独立保留，讨论共识另报；小样本一致率不代表审核无偏。
- [ ] E=四图F均yes且至少两图D=yes；S单报。联合率为`E且Order正确`除固定40，不以仅答对样本为分母。Unclear、模型缺项及未完成人工标签分别列出。
- [ ] 没有真人标签时E/joint必须pending/null；自动评测完成不能写整个E4人工审核已完成。两名人类审核不能由代理视觉判断冒充。
- [ ] 同题answer-only与process prompt变化说明任务提示效应，不能直接归因训练。证据仅支持显式输出质量，不推断内部推理faithfulness。

## 对不同结果的结论模板

| 正式观察到的模式 | 可以写的结论 | 还需核查 |
|---|---|---|
| Pair可区分组更多，持出Exact差值区间跨零 | 增加反馈可用性，当前预算与seed下的全序收益仍不确定 | 更新有效性、格式、SFT预算和区间宽度 |
| Pair或部分关系提高，Exact/B未同步改善 | 收益集中于局部/平均呈现，尚未证明完整且严格稳定正确 | 六关系、q分布、相同子集、B边界退化 |
| C提高但A不提高 | 预测更一致，未转化为更高正确率 | 是否稳定重复错误及invalid变化 |
| SFT性能/成本更好，或四pass对照削弱RL优势 | 在明确预算和任务范围内SFT更合适，或RL优势受监督预算限制 | 相同W、曝光、选点和完整成本 |
| Pair在Exact与E3上均改善 | 在该任务、该共同预算和已运行seed下观察到收益 | 训练seed不确定性、人工依据、歧义及复跑边界 |
| 无非零信号、无有效权重变化、映射或输入失效 | 实施验收未通过，尚无算法优劣的科学负结果 | 修复后完成必要分支，保存失败日志 |

任务结论限于RecipeQA文字引导的真实步骤照片排序及呈现鲁棒性。官方食谱split隔离不等于跨任务类别、视频运动理解或公开预训练污染已被排除。报告和demo应以一条数据支持的行为发现为主线，案例配总体比例；结果不符合预期时保留所有分支与限制。
